# Implementation Plan: Slice 2 — Vendors

**Branch**: `003-vendors` | **Date**: 2026-11-06 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/003-vendors/spec.md`

## Summary

The one shared vendor list every order will reference (brief §3.1):
- create, list (active by default, status filter, name prefix), read, full-replacement
  edit, deactivate and reactivate, all by any Buyer; reads for every role
- a normalised unique name enforced by PostgreSQL; the `409 DUPLICATE_VENDOR_NAME` names
  the existing vendor in `existingVendor: { id, name }` (ADR-0007 amended)
- one contact person; `contactPhone` is `null` when absent, never `""`
- structured payment terms (NET, ADVANCE, PARTIAL_ADVANCE) checked by schema and by the
  database
- `If-Match` versioning; vendor history from the audit trail for Buyers and Admins
- `requireActiveVendor` and `VendorSnapshot` for the order slices
- the web app's vendor screens, deactivate dialog and history tab

Design choices are in [research.md](research.md) (R1–R13), tables in
[data-model.md](data-model.md), and the reviewed Zod schemas, operations and OpenAPI diff
in [contracts/api.md](contracts/api.md), with [errors.md](contracts/errors.md) and
[ui.md](contracts/ui.md).

## Technical Context

**Language/Version**: TypeScript 6 (`strict`) on Node.js 24; SQL for PostgreSQL 17

**Primary Dependencies**: slice 0–1 stack; no new dependency.

**Storage**: PostgreSQL 17. New table `vendors`; new index on `audit_entries` (migration
`0011_vendors`).

**Testing**: Vitest + Supertest + Testcontainers PostgreSQL 17 (no DB mocks), a plan
test with a fixed-seed dataset, Testing Library + vitest-axe + MSW, Playwright + axe.

**Target Platform**: the existing docker compose stack; no new service.

**Project Type**: web application (API + SPA), npm workspaces.

**Performance Goals**: list and history pages served by index scans at 2,000 vendors and
about 2M audit entries (ADR-0012, amended 2026-11-06), plans committed (R11); plan tests
run on backend/contracts PRs, every push to `main` and nightly; committed plans are
`EXPLAIN (COSTS OFF)` shape only; route chunk ≤ 150 KB gzip.

**Constraints**: strict bodies; deny by default; no vendor delete on any path; `""` never
stored for an optional field; vendor contact details kept in full in audit (ADR-0016).

**Scale/Scope**: 7 operations, 1 table + 1 index, 3 error codes + 1 field code, 4 audit
events, 4 screens, 1 dialog.

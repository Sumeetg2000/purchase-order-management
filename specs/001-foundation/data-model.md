# Data Model: Slice 0 — Foundation

Slice 0 creates only what the foundation needs: the audit trail, a minimal user record for
the bootstrap admin, and one-time tokens. Later slices add columns and tables through new
migrations; nothing here is final for `users`.

Conventions:
- All timestamps are `timestamptz`, set from the database clock.
- IDs are UUIDv7 (time-ordered), generated by the application, except `audit_entries.id`.
- Every table is owned by `po_owner`. Privileges are granted explicitly; `PUBLIC` has none.

## users (minimal)

| Column | Type | Rules |
|---|---|---|
| `id` | uuid | PK |
| `name` | text | 1–100 characters (`CHECK`) |
| `email` | text | stored lower-cased (`CHECK email = lower(email)`), `UNIQUE` |
| `roles` | text[] | `CHECK` that the value is exactly one of `{}`, `{BUYER}`, `{APPROVER}`, `{BUYER,APPROVER}`, `{ADMIN}` (sorted, so `{APPROVER,BUYER}` is normalised before insert) |
| `status` | text | `UNVERIFIED` \| `ACTIVE` \| `DEACTIVATED` (`CHECK`) |
| `deactivated_at` | timestamptz null | `CHECK (status = 'DEACTIVATED') = (deactivated_at IS NOT NULL)` |
| `password_hash` | text null | null until a password is set (the bootstrap admin starts with null) |
| `version` | integer | starts at 1; incremented on profile, role and status changes (ADR-0016) |
| `created_at`, `updated_at` | timestamptz | defaults `now()` |

- Triggers: `require_actor_context` on insert, update and delete.
- Privileges: `po_app` gets `SELECT, INSERT, UPDATE`, never `DELETE`, because users are
  never deleted. `po_maintenance` gets nothing in slice 0. Slice 1 grants it
  `UPDATE (phone)` when the phone column is added.
- Slice 1 adds `phone`, `last_login_at`, `failed_login_count` and `locked_until`.

## one_time_tokens

| Column | Type | Rules |
|---|---|---|
| `id` | uuid | PK |
| `user_id` | uuid | FK → `users.id` |
| `purpose` | text | `RESET` \| `VERIFY_EMAIL` (`CHECK`); only `RESET` is used in slice 0 |
| `token_hash` | bytea | SHA-256 of the 256-bit token, `UNIQUE`; the raw token is never stored |
| `expires_at` | timestamptz | `RESET` = created + 30 min; `VERIFY_EMAIL` = created + 24 h |
| `used_at` | timestamptz null | set once; a used token is invalid |
| `superseded_at` | timestamptz null | set on earlier unused tokens of the same user and purpose when a new one is issued |
| `created_at` | timestamptz | default `now()` |

- Index: `(user_id, purpose) WHERE used_at IS NULL AND superseded_at IS NULL`, for
  superseding.
- Index: `(COALESCE(used_at, superseded_at, expires_at))`, for the purge. It's the same
  expression as the purge rule, so the purge can use it.
- Privileges: `po_app` gets `SELECT, INSERT, UPDATE`. `po_maintenance` gets
  `SELECT, DELETE`.
- Validity rule (used from slice 1): a token is valid only when `used_at`, `superseded_at`
  are null and `expires_at > now()`. Every other case is `INVALID_TOKEN`.
- Purge rule: delete when `COALESCE(used_at, superseded_at, expires_at) < now() - 7 days`.

## audit_entries

| Column | Type | Rules |
|---|---|---|
| `id` | bigint identity | PK; the sort tiebreaker |
| `occurred_at` | timestamptz | default `now()` |
| `actor_type` | text | `USER` \| `SYSTEM` \| `OPERATOR` |
| `actor_user_id` | uuid null | no FK (actors are never deleted, and entries must stand alone) |
| `actor_name`, `actor_email` | text null | snapshot at the time of the entry |
| `acting_role` | text null | e.g. `ADMIN`, `APPROVER` |
| `action` | text | e.g. `ADMIN_CREATED` |
| `entity_type`, `entity_id` | text | e.g. `user`, the user id |
| `order_id` | uuid null | for order events (slice 3 on); no FK |
| `po_number` | text null | for order events |
| `details` | jsonb | before/after and event-specific fields; never a phone number |
| `request_id` | text null | correlation id or CLI run id |

- `CHECK` that ties the actor fields to `actor_type`:
  - `USER`: `actor_user_id`, `actor_name`, `actor_email` and `acting_role` are not null.
  - `SYSTEM`: all four are null.
  - `OPERATOR`: `actor_user_id` is null, and `details ? 'osUser' AND details ? 'host'`.
- A `BEFORE INSERT` trigger fills the actor fields and `request_id` from the transaction's
  actor context. It raises `ACTOR_CONTEXT_REQUIRED` (SQLSTATE `PO001`) if there is none,
  and `ACTOR_CONTEXT_MISMATCH` (`PO002`) if explicit values contradict the context.
- Index: `(occurred_at, id)`. Slice 1 adds the organisation-wide log's filter indexes.
- Privileges: `po_app` gets `SELECT, INSERT`, never `UPDATE` or `DELETE`.
  `po_maintenance` gets `SELECT, DELETE` (purge after 8 years) and `INSERT` (for
  `USER_PHONE_PURGED`, used from slice 1).

## Actor context (transaction-local settings)

Not a table: set at the start of every transaction by `withTransaction` (research R6), and
gone at commit or rollback.

| Setting | USER | SYSTEM | OPERATOR |
|---|---|---|---|
| `app.actor_type` | `USER` | `SYSTEM` | `OPERATOR` |
| `app.actor_user_id`, `app.actor_name`, `app.actor_email`, `app.acting_role` | set | — | — |
| `app.os_user`, `app.os_host` | — | — | set |
| `app.request_id` | correlation id | job run id | CLI run id |

## Error code (registry, not stored)

`code` (UPPER_SNAKE_CASE, unique) · HTTP `status` · `title` · `fieldDetails` (whether
`details[{ path, code }]` applies). Lives in `packages/contracts/src/errors.ts`. The codes for
slice 0 are listed in [contracts/errors.md](contracts/errors.md).

## _prisma_migrations (created by Prisma)

Owned by `po_owner`. `po_app` gets `SELECT` only, so readiness can confirm that no
migration is pending or failed. `po_maintenance` gets nothing. Granted in the baseline
migration.

## Database functions and advisory locks

| Name | Purpose |
|---|---|
| `require_actor_context()` | trigger function; refuses audited changes without context |
| `audit_fill_actor()` | trigger function on `audit_entries`; fills and verifies the actor fields |
| advisory lock `ADMIN_LOCK` (constant) | bootstrap and every operator CLI command |
| advisory lock `PURGE_LOCK` (constant) | the maintenance purge |

## Reconciliation query

`db/reconciliation.sql` exists from slice 0 and returns zero rows, because no derived value
exists yet. Slice 3 adds INV-1 to INV-6 checks to it. CI runs it after the test suite from
this slice on, so the wiring is proven early.
